# 文件整理、回收站与删除影响

## 使用入口

- 文件列表、文件详情、数据集文件夹内的文件操作提供“整理”：在当前数据集的已有文件夹之间移动，或修改文件名称。文件扩展名保持不变，MinIO 路径同步更新。
- 点击“删除”直接执行回收，不再弹出影响确认。系统仍检查版本引用及权限；不能删除或执行失败时展示具体原因，可处理草稿引用后重试。
- 左侧“回收站”支持搜索、分页、单个和批量恢复。一级管理员可单个或批量彻底清理，点击操作直接执行，不需要额外确认勾选。

数据集删除直接提交清理任务，自动携带当前数据集名称。移动、重命名和解除引用保留必要的填写或选择表单，提交后直接执行。冻结及发布在完整性校验通过后直接执行；离开草稿编辑不再弹出放弃修改确认。权限、CSRF、历史版本、引用和并发检查继续生效。

## 回收与恢复规则

删除文件会在同一数据库事务中保存文件元信息和标签，再移出活动文件表。原 MinIO 对象保留在原路径，正常列表、搜索和 AI 文件查询不再返回它。被版本引用的文件仍不能直接回收。

回收站显示移入时间和 30 天后的建议检查日期；到期不会自动删除，仍可恢复。永久清理由管理员明确执行。恢复保留原 ID、原目录、文件内容、元信息和仍存在的标签，不会自动重新创建已经解除的版本引用。

恢复遇到同名文件、相同内容、同名文件夹、正在上传的同名文件、原目录/数据来源缺失或权限变化时，会保留回收记录并提示处理。数据集还有回收文件时，需先恢复或彻底清理，才能删除数据集。

## 路径与历史版本保护

当前支持同一数据集内移动，不跨数据集迁移。未归属数据集的旧文件仍可回收、恢复，但不支持整理路径。目标已存在时不会覆盖；草稿版本继续引用同一个文件 ID。冻结、已发布、归档或无权限的版本引用会阻止路径变更。

移动使用对象存储服务端复制，校验大小后提交新路径，最后删除旧对象。复制或元信息提交失败时保留原文件；旧对象清理失败时提示管理员使用存储扫描处理。版本时间戳与锁保护并发冻结操作。

存储扫描将回收站对象视作受管理对象。执行已有孤立对象清理任务时，会重新检查活动文件、回收站、版本和文件夹归属，避免使用过期扫描结果清理已受管理的数据。

永久清理在删除对象前持久化清理状态；存储失败可重试，但不能在对象可能已删除时恢复文件。

## 接口

所有接口沿用会话认证、权限范围和写操作 CSRF 校验。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/files/:id/delete-impact` | 引用、回收阻碍与路径变更可用性 |
| PATCH | `/api/v1/files/:id/location` | `originalName`、`folderPath`、`confirmed: true` |
| DELETE | `/api/v1/files/:id` | 移入回收站，返回 204 |
| GET | `/api/v1/files/recycle-bin` | `page`、`pageSize`、可选 `search` |
| POST | `/api/v1/files/recycle-bin/:id/restore` | `confirmed: true`，恢复 |
| POST | `/api/v1/files/recycle-bin/:id/purge` | `confirmed: true`，永久清理 |

部署需应用迁移 `20260923100000_file_recycle_bin`，只新增回收表，不删除或改写已有文件数据。


### 大文件上传策略

分片上传不再设置固定 2 GiB 单文件业务上限。`upload.*MaxBytes` 默认为 `0`，表示不设置该类型的业务限额；管理员仍可设置正整数上限。已存在的正数策略继续生效。分片保持 8 MiB，当前对象存储最多合并 10,000 片，因此单次会话的协议容量为 78.125 GiB；可用空间、磁盘保留和缓存配额仍独立生效。

原始视频、校验和、数据集版本校验及发布快照均逐块处理，不把整个文件读入内存。完整结构解析另有内存预算：JSON 为 50 MiB，YAML 为 10 MiB，超过预算会明确返回格式校验错误。分片校验、最终 SHA-256、大小比对和上传权限规则继续保留。
