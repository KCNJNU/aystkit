# 关键故障日志

入口为观测网页左侧 **关键故障**，或 `https://aystkit.cn/#logs`。已批准的观测账号可查看及下载；未登录与待审批账号不能访问日志接口。页面每 5 秒刷新，后台采集与服务器存储不依赖浏览器打开。

## 传感器分类与报错含义

分类卡可查看三维激光雷达、二维激光雷达、惯性传感器、普通相机、深度相机、雷达与惯性融合，以及定位导航、底盘、工控机、网络链路和系统其他问题。卡片条数对应全部保留记录；列表的“共 N 条”对应当前时间、级别、分类和关键词筛选。选择分类后，分页与 CSV / JSON 下载使用同一范围。

每条记录默认显示中文设备名称、报错标题及含义。“详情与原始记录”中保留可能影响、排查建议、原始消息、来源节点、异常代码和证据。中文解释描述已观察到的现象；可能影响与排查方向不代表已经确认硬件损坏、网络拥塞或障碍物真假。无法确认设备或具体原因时会明确标为待确认，不按日志中偶然提及的设备名称猜测根因。

分类与释义在读取时派生，既有历史无需改写。CSV 保留原有 13 列顺序，并在末尾追加分类、设备、中文标题、含义、影响和建议；JSON 包含相同派生信息。可以直接搜索设备名或中文含义。

## 时间和下载

列表显示北京时间（毫秒）、级别、异常代码、来源、原始详情、首次与最近发生时间，以及累计发生次数。相同来源的同类关键故障在连续 10 分钟接收窗口内合并；已知关键类型按异常代码和组件归组，原文中变化的数值不会拆成多行。首发立即记录，采集端每 5 分钟补充重复次数，不另开“重复故障汇总”行。新记录按每批 `details.occurrences` 精确累加，列表次数包含采集端限频期间实际观察到的次数，原始详情保留最新证据及被合并事件的首末时间。

历史日志通过只读分组视图收拢同类问题，不删除或改写原始行。升级前的合并摘要若只保留了最新一次 `suppressed_count`，历史次数按现存证据可确认的下界显示，并保留原始详情；不推算缺失的重复次数。

时间筛选输入按北京时间解释。CSV / JSON 导出的是全部符合筛选条件的记录，不受当前分页限制。CSV 含 UTF-8 BOM、北京时间时区及原始秒时间戳，适合表格软件；JSON 保留结构化证据。CSV 对公式前缀加保护，原始内容以 JSON 为准。

事件 `timestamp` 是采集端发现异常时的墙钟时间；雷达、IMU、ROS 日志中的原始时间保留在 `details`，用于分析时间戳回退。`received_at` 是云端接收时间。断网补传时两者可以相差较大。

## 记录范围

只记录 **ERROR / FATAL 严重故障**及下列明确影响定位、控制或数据链路的**关键告警**。普通 ROS 警告、正常启动和恢复信息不再进入故障日志。升级前的记录不删除；列表、统计和 CSV / JSON 下载统一按此范围筛选。

- 雷达 / IMU 采样时间断档、回退、时间同步失败。源时间间隔大于 0.5 秒（雷达）或 0.25 秒（IMU）时记录断档；这些是监测阈值，不是设备额定采样周期。
- Livox 点时间回绕或倒序的直接证据，以及来源日志明确报告的同类异常。正常的跨消息相对时间归零不会当作回绕；直接检查最多抽样 1,025 个点，不保证发现任意单点异常。
- 来源日志或诊断明确报告的定位丢失或异常、控制器反复转向、导航超时或失败、障碍触发停车，以及 Nav2 动作失败终态。本模块不根据运动轨迹主动推断定位故障或转向振荡。
- 已运行设备数据中断、相机预览中断、观测采集心跳超时。恢复状态仍在设备页面显示，不再逐条写入故障日志。
- 工控机温度达到 85°C 的监测告警，以及异常发生时已有的温度和网络速率上下文。该温度值是日志监测阈值，不代表硬件降频温度。
- 节点明确报告的错误或严重故障、严重诊断异常，以及故障监测受限或离线队列溢出。

从未收到过数据的设备不会仅因未启动而报断连；主动停止过的设备也可能产生“已运行数据中断”记录。采集心跳在线不代表全部设备正常。日志只记录直接观察或来源明确报告的证据，不推断控制器误差不匹配、障碍真假或硬件故障；安装资料缺失和地图误标记仍需人工确认。

## 存储与边界

工控机独立只读 Collector 使用 `~/.local/state/robot-cloud/faults-<source>.sqlite3` 持久保存最多 10,000 条待发送事件。只在收到明确服务器成功回执时删除对应事件；进程重启和短暂断网后会继续补传。队列满时移除最早事件，并记录 `FAULT_LOG_OVERFLOW` 及累计移除数。

云端日志及事件去重表位于现有 `/data/latest.sqlite3`，日志与上传顺序检查点在同一事务提交。日志按接收时间保留 30 天、最多 20,000 条，去重回执最多 100,000 条。新表兼容旧版服务回滚，备份 `/data` 应包含完整 SQLite 数据。只记录新启用后的证据，不伪造启用前的故障历史。正常初始化不再写入 `FAULT_MONITOR_STARTED`；采集状态由既有心跳和设备状态提供。

模块只订阅数据和读取已知日志，不发送运动指令、不修改导航容差、避障范围或传感器时钟。加载采集更新只需精确重启 `robot-cloud-collector.service`，无需重启导航或相机。
