# 地库原生数据自动归档

## 当前桌面采集约定（2026-11-04）

桌面采集入口为 `~/桌面/camera-section-tool/launch_sensors.sh`，默认开启或复用相机后录制，雷达无需预先开启。工控机只读检查现有 MID360/IMU、STL-19P 和蓝海二维雷达，不启动或等待雷达驱动；未运行或检查超时不会阻止相机准备及录制。Jetson 继续开启或复用 Berxel 彩色/深度、共享四路 USB 相机、固定 by-id 已连接的鱼眼相机、源端归档及只读预览；保留已运行的 YOLO/ArUco，默认不额外启动识别服务（需要时显式加 `--with-camera-yolo`）。不会启动 FAST-LIO、导航、建图或恢复旧点云归档策略。可用 `--no-device-start` 选择只录已有数据。网页“地库自动采集”只控制 `garage.json`；桌面使用独立短期租约，不开启网页自动采集。

### 与导航、建图共用雷达

2026-11-01 19:27 的用户服务日志确认，旧版全设备采集路径曾通过 `robot-device-mid360.service` 启动 Livox 驱动、FAST-LIO、里程计和 TF。导航、建图自己的设备入口也会启动这条链路，叠加运行存在重复驱动、端口和 TF 冲突；停止旧采集还会停止它拥有的雷达链。未找到当时导航进程的端口绑定报错，不能仅凭这段日志断言所有断流均来自同一原因。

当前桌面入口对 IPC 使用 `device_sources.py ipc --recording-only --status`，雷达检查最多8秒，仅发现已有驱动及其实际配置，不检查硬件可达性、不申请UDP端口、不启动或接管驱动。Jetson 相机沿用原有启动流程。归档进程无雷达消息时可进入 `WAITING_UPSTREAM` 并开启录制；之后在同一 ROS/DDS 图上出现的雷达数据由现有订阅接收，无需重开采集。若后来启动的雷达使用不同域、中间件或发现配置，仍需核对通信，不能把没有收到的数据显示成成功。

已有已核验雷达时，录制前的 DDS 图一致性检查仍保留，且仅可调整空闲归档接收器；不修改或重启雷达、导航和建图。雷达缺失会在进度和结束报告中明确显示，并把本次标记为不完整，已保存视频保留。正常结束先释放录制租约、等待队列封片，再按本轮启动身份收尾专属辅助服务。USB、Berxel 深度和彩色、鱼眼等共享相机源保持运行，防止中断随后接入的算法；结束录制不等于关闭全部设备。已有辅助服务、其他采集入口已打开、身份无法确认或停止存在依赖联动时均保留。需要关闭全部设备时使用明确的设备关闭入口。

`tests/test_archive_dds_coexistence.py` 提供显式启用的 DDS 共存验证：独立非零域内的三个测试子进程分别发布合成 MID360/IMU、模拟算法订阅、通过真实 ROS bag 写入归档，验证关—开—关窗口接收连续以及发布者不被停止。该测试不启动真实设备、不修改生产 DDS 配置；合成低负载测试通过不代表实车雷达、视频与磁盘满载验收完成。

### 采集资源与后台上传

实时归档接收与写盘保留原有服务调度（Nice 10、I/O best-effort 7）。视频封片、无损压缩和自动上传的后台线程单独退让为 Nice 15、I/O idle，所启动的编码、压缩子进程继承该优先级；桌面独立上传也采用此后台优先级。设置失败会记录警告并保留正常处理与原件，不使用硬性 CPU 配额、缩减内存或更改帧率来隐藏资源问题。

`ARCHIVE_UPLOAD_BYTES_PER_SECOND` 独立控制数仓文件上传速率，默认 `1048576`（1 MiB/s）；在私有 `~/.config/robot-cloud/archive.env` 中设置非负整数字节数，`0` 才显式不限速。8 MiB 上传分片按 64 KiB 小块发送，保留固定 Content-Length、分片校验、断点续传与完整入仓回执；登录、状态、关闭确认等元数据请求不占视频上传预算。预算按每个上传客户端跨文件、分片和重试延续，长时间空闲不积攒突发流量；并行前台、后台客户端各有独立预算。Jetson 到工控机的文件回传仍由原有 `ARCHIVE_TRANSFER_BYTES_PER_SECOND` 控制，不能用它替代公网上传限速。

这些措施减少资源争用，不能保证任意负载下对算法零影响。现有已启动进程需要在空闲时正常刷新才会加载 Python 变更；不应为应用优先级而中断正在录制或使用相机的算法。导航、建图与采集同时工作的真实吞吐及延迟仍需现场验收。

### 两个桌面脚本的完成状态

设备启动会逐项报告已启动、复用、部分可用、未连接或失败，长时间检查每 15 秒显示仍在运行，Ctrl+C 可取消后续启动。录制开始后会立即显示状态，此后状态变化或每 15 秒显示已运行时间、视频和雷达是否真正写盘、相机主机是否连接。仅服务/驱动进程存在不表示收到数据；缺失设备不会伪报成功，会继续保存其余可用数据并将本次标为未完成。设备报告也保存在本次 `desktop-capture.json`，可通过 `--status` 查询。

源端启动使用固定受信 SSH 的独立心跳通道，每 2 秒续一次，远端 EOF 或 10 秒无心跳即中断后续启动动作；只取消本次启动 helper，不停止已经运行的设备。此机制只覆盖车内启动请求，不参与录制期间的 20 秒桌面租约，不依赖外网。

在终端无参数直接打开两个脚本时，结束后保留结果窗口，按 Enter 关闭；上传显示中文数量摘要，并区分已入仓成品与历史待封片文件。参数调用和非交互任务默认不等待输入，原生归档可用 `--pause`、`--no-pause` 显式选择。真实运行的输出保存在 `~/.local/state/robot-cloud/desktop-logs/`，按工具保留最近 20 个日志；预演、帮助和只读状态查询不生成日志。

采集窗口启动阶段收到结束信号时，不再开启新的采集租约；状态诊断失败也先关闭本次租约。停止命令核对开机标识及进程启动时间，旧开机留下的 PID 标记不能用于停止当前进程。两个入口固定从配置的归档包加载程序，不随调用者所在目录切换到同名 Python 包，相对数据路径仍以调用者目录为基准。

“上传本地采集数据”默认上传当前原生归档，不再因为旧目录中存在一个已完成会话就切到旧上传器。`--archive-root DIR`、`--env-file FILE`、`--timeout 秒数` 用于原生归档；旧会话通过 `--root DIR`、`--latest` 或 `--session ID` 显式选择，不能与前述原生选项混用。`--dry-run` 只读，不启动服务、不修改开关、不生成 Python 字节码。

上传结果的范围始终是本机快照（`scope=local-sealed-snapshot`、`remoteSync=not_checked`），不代表 Jetson 上的全部数据已同步。待封片/压缩、仍在录制或拉取中的文件分别计入 `preparingSegments`、`activeSegments`、`stagingSegments`，有未完成内容时返回未完成，而非仅凭已封片文件都上传就报告成功。历史 recovery 原件单独提示，不擅自删除。超时覆盖扫描、校验和 HTTP 请求全程；单个坏清单、状态或回执不再阻止其他正常片段，网络和认证等全局故障按退避重试。

本次需要的是视频和雷达训练数据。IPC 的 MID360、两路二维雷达及配套信息保持原选择；Jetson 新采集选择为 `Berxel彩色,Berxel深度,鱼眼相机`，USB 相机由原共享读取进程接入，不再额外记录 Berxel 深度派生点云。根据用户“用途未确定，尽量保留后续训练能力”的选择，新深度片段使用 `ARCHIVE_DEPTH_VIDEO_MODE=lossless`，以 FFV1 保留 ROS 已发布的 16 位深度值；历史伪彩片段不重写，不能从中恢复原始距离值。彩色视频保持现有 HEVC 设置，雷达保持原采样和 Zstd 3 级无损压缩。原画质临时文件在压缩成品完成本地验证后清理；成品在数仓确认保存之前保留，历史坏片段不会冒充成功。

为减少采集期间的临时磁盘占用，两端设置 `ARCHIVE_CAMERA_SEGMENT_BYTES=134217728`，Jetson 的私有 `native-camera-archive.json` 同时设置 `segmentBytes=134217728`。新相机原始中转片段从 512MiB 缩至 128MiB，非图像 ROS 包仍为 128MiB。这使原始帧更早进入压缩与清理流程，降低未封片及编码工作区峰值，不改变原帧数和雷达点字段，也不会按比例减少成品总量。已启动的 USB 进程只在下一次正常启动时读取 JSON，不能为应用配置接管或重启其他人的相机。后台清理逐分片验证数仓回执；一个分片上传失败不再阻止其他已确认副本释放空间，失败或未确认的原件继续保留。

外网中断 10 分钟不会使 IPC 本机续租停止；车内 IPC—Jetson 链路仍需保持连接。20 秒租约用于清理意外退出的桌面会话，不应改成无限期限。正常结束会先停止新消息入队，排空已接受的视频帧和雷达消息，再关闭片段。ROS、相机队列仍有容量上限，存储保护仍为每端约 20 GiB 缓存阈值和 10 GiB 空闲预留；并行写入和压缩可能短时超过阈值，且该阈值不包含数仓 Docker 卷。编码积压或空间不足会明确报错，不能承诺任意负载下零丢帧。此前六路伪彩/彩色视频加 MID360 约 1.82 GiB／10 分钟、约 35GB／3 小时是旧深度策略的历史估算；切换真实深度无损保存后，需重新测量体积和编码吞吐。尚未做同时导航的现场十分钟验收。

当前正式数仓的数据库与对象仍在 IPC，所以公网数仓登录暂时依赖小车隧道，缓存清理也不代表数据已离开小车硬盘。用户扩容后再按 [云数仓迁移说明](warehouse_cloud_migration.md) 完整迁移；迁移未执行前，不能声称离线登录问题已解决。以下早期部署记录中的深度点云选择、原始缓存保留、相机分片大小和深度编码描述，以本节当前配置为准。

在白色数仓侧栏下方的“地库采集”独立页面 `/dbprog/garage-archive` 操作。进入地库开启，离开时关闭；选择跨重启保留，默认关闭。数仓账号需管理员权限才能更改开关。机器人上传使用独立数据项目的 OPERATOR，不复用管理员账号。

当前恢复原架构的全传感器保存：工控机本地保存 MID360/IMU、两路二维雷达、定位与 TF、底盘遥测、诊断和覆盖任务；Jetson 本地保存四路普通相机、P100R 彩色/深度/点云及可用的鱼眼数据。两端先落盘，工控机再通过固定私有 SSH 拉取 Jetson 已收尾片段并上传数仓。逐帧时间戳、相机标定 `CameraInfo` 和原始 ROS CDR 均保留；没有发布者的话题只显示等待，不生成伪数据。此选择只影响归档，不关闭设备或实时观测话题。已有正式数据集及历史待处理原件保持原样。

归档目录示例：

```text
地库_2026-10-30/
  原相机前/
    原相机前_14:50-15:50/
      <片段编号>/video.mkv
  Berxel彩色/
    Berxel彩色_14:50-15:50/
      <片段编号>/video.mkv
  Berxel深度/
    Berxel深度_14:50-15:50/
      <片段编号>/video.mkv
```

数仓目录浏览会在时间段内直接列出片段文件，隐藏自动生成的片段编号文件夹；同一时间段的多个片段分别保留，按录制时间或片段标签区分。该展示不移动、重命名或删除对象，原始路径和片段编号仍用于校验、补传及追溯，普通数据集目录保持原样。

按北京时间分日；时间段来自真实接收时间，最长一小时；相机原始中转片段达到512MiB，相机标定信息独立中转片段达到128MiB，或原始数据停止15秒，会提前收尾。重启、跨天或大小切分可能出现更短时间段；唯一片段编号防止同分钟覆盖。开启后自动建立当日数据集和所选相机目录；空目录不表示收到数据。

当前正式部署使用工控机上的 MinIO 对象存储，文件落在工控机 NVMe 硬盘的 Docker 持久卷 `robothygienism_minio_data`；PostgreSQL 保存文件索引、SHA256、传感器、时间和数据集信息。ROS bag 的 `.db3` 是原始 ROS 文件格式，不能作为另一个业务数据库。保留 CDR 消息原字节和内部 ROS header，未走网页缩图/抽点/压缩桥。USB 相机直接在原有唯一采集进程读出相机 MJPEG 后、网页 H.264 编码前分支保存。新建片段保留 `archiveProfile=compact-v1`，彩色视频默认使用 `videoArchivePreset=720p-balanced-v1`：在原始帧完整落盘后，采用 Jetson HEVC 约 2 Mbps 编码，等比缩放至最高 1280×720（4:3 画面为 960×720），不放大、不裁剪，保留全部帧和原始时间。缩小时使用 VIC Nicest 插值。颜色编码有损，元数据分别记录源尺寸、输出尺寸和实际像素格式；CameraInfo 附件仍对应源分辨率，基于缩放视频使用相机内参时须按尺寸比例换算。已有显式省空间策略 `720p-economy-v1` 恢复时沿用 1.2 Mbps；历史未标记此类策略的片段维持原有处理方式。压缩候选比原质量 MKV 更大或硬件不可用时保留已校验的原质量 MKV，并在元信息记录回退原因。16 位深度始终使用 FFV1 无损 MKV，逐像素回解校验。每路相机每个片段入仓一个 `video.mkv`；逐帧时间戳、源编码、原件校验信息和 CameraInfo 原 CDR 作为视频附件保留，不上传一串图片。源帧校验值用于追溯原始采集，并不等于有损视频解码像素的校验值。接收时刻不是硬件曝光时刻。

CameraInfo-only 片段属于相机配套，仍可采用标准 rosbag2 Zstandard 文件压缩（level 3、单线程），保留解压后原 `.db3` 的完整字节；发布前完整流式解压并校验 SHA256、字节数和消息数。已有非相机 bag 的兼容代码保留，但仅相机策略下不会处理其历史待封装或待上传清单，不补写成功回执，也不清理这些被排除的原件。已有正式清单、仓库对象和历史数据集不迁移、不删除。混合图像与点云的话题清单会被拒绝，不以“相机”目录名冒充相机数据。

工控机归档器使用 `ARCHIVE_CAMERA_ONLY=0` 和 `ARCHIVE_ROS_SENSORS=雷达MID360,二维雷达scan,二维雷达蓝海,定位与TF,底盘遥测,诊断日志,覆盖任务`，直接订阅本机已运行的雷达与遥测源。Jetson 使用 `ARCHIVE_CAMERA_ONLY=0` 和 `ARCHIVE_ROS_SENSORS=Berxel彩色,Berxel深度,Berxel点云,鱼眼相机`，就地订阅 P100R 与可用鱼眼话题，并在原 USB 相机进程启用既有 JPEG tap。空白的 `ARCHIVE_ROS_SENSORS` 代表全部固定白名单；显式 `none` 才表示不建立 ROS 订阅。两端按物理设备分工，避免把原始相机或点云通过跨机 DDS 重复传输；工控机 source-link 只拉取 Jetson 已收尾文件，再统一上传。

后台录制器本身只订阅话题，不管理设备；桌面入口负责上述最小驱动启动，输入缺失时显示等待相机原始数据。所有队列有条数和字节上限，掉样/缺流/写入错误分别计数，不以零已检测丢弃宣称绝对无损。

## 断网与断电

工控机和 Jetson 都先本地落盘，原始实时图像不跨无线网传来录制。工控机通过固定受信主机的现有私有 SSH 连接拉取 Jetson 已收尾的原始文件，完整校验后再调用工控机本地 `127.0.0.1:3000` 数仓 API 入仓。源机没有数仓登录凭据，不创建 API 转发端口；文件传输与地库开关同步分别运行。

8MiB 分片及每片 SHA256、uploadId、服务器已有 parts 均持久化。HTTP202/FINALIZING不表示入仓成功；服务器完成和文件信息完整校验后才生成 uploaded.json。已有片段保留原5分钟中转保留期。新 compact 片段在上传确认后，再次验证本地校验和及当前数仓对象可访问，立即清理设备上的重复中转副本，避免重复缓存挤满磁盘；数仓的正式对象继续保留。视频封装前的 JPEG/index 或原图 bag 仅作内部中转与恢复，按同样确认规则清理。未完成入仓、校验失败或断电损坏的原件不会被自动清理。默认中转缓存20GiB、磁盘预留10GiB；达到保护线停止新增写入并提示，不能用抽帧伪装继续保存。

视频封装与相机标定 bag 配套压缩各用一个独立后台线程，不阻塞相机原始数据写盘线程；失败保留待封装清单和原件，重启后重试。一帧、几秒短录均生成正时长 MKV，正常关闭须等封装结束才报告完成。HEVC/MJPEG/FFV1 MKV 可从文件列表或详情页下载后，用支持对应编码的播放器或数据工具打开，不承诺浏览器原生播放。实际空间节省随场景变化，强噪点会降低视频可压缩程度。

ROS bag 使用 resilient 写入配置；重启时验证原 bag 并重建索引，可恢复的消息标明断电中断。JPEG 仅恢复完整且逐帧校验通过的索引前缀；坏尾保存在 recovery。不把截断片段假标为完整采集。

地库开关在工控机保存，由私有源连接每5秒同步并确认。Jetson暂时断联时按上次地库设置继续本地保存；关闭开关尚未送达时，数仓明确提示源端尚未确认，需要恢复车内连接。源端恢复后自动收到最新开关。车内 Jetson 与工控机之间的归档回传及预览 SSH 已固定走有线 `192.168.1.50`，使用原有主机公钥身份；热点地址变化或 mDNS 不通不会再中断这条车内链路。

公网链路直连 HTTPS 优先，显式配置的代理仅在连接失败时回退，失效代理冷却60秒，预览帧自身的新鲜度超时不会单独触发换路；保持 TLS 验证和禁止重定向。隧道自动跟随当前网络出口，Jetson 使用 mDNS 地址并固定已有主机公钥身份，避免 DHCP 换址后还连旧雷达网口。断电重启后隧道重连。没有可用蜂窝/Wi-Fi出口时，实时网页仍需等待网络恢复，现场原始采集独立继续。

## 相机采集与保存状态

“地库采集”页面直接显示前、后、左、右及深度彩色／深度六路状态，分别报告采集、保存、真实帧计数和最新帧年龄，每 5 秒刷新。USB 状态只读取已有相机网关元数据，不打开相机；“采集中”要求收到新鲜帧，“正在保存”要求连续源端快照中的已写入帧数增长。累计帧数或服务在线不能单独证明仍在采集。缺失或过期的状态显示未知／过期，缺失计数显示 `--`。深度相机使用源端原始图像接收证据；归档关闭且没有该证据时显示未知。

状态检测不会开启设备或地库开关，也不会修改视频分段规则。时间戳目录增多须结合片段清单 `metadata.closeReason` 判断：`rotation` 为时间／大小切分，`idle` 为断流收尾，`storage_paused` 为存储保护，`garage_disabled` 为关闭采集。高码率图像可能在一分钟左右达到 512 MiB，因此目录数量不能单独用来推断网络断流。

## 服务与检查

工控机和源机：`systemctl --user status robot-native-archive.service`。工控机另有 `robot-native-archive-source-link.service` 同步门禁并拉取已收尾原始文件。两台已具备 linger，归档服务启用用户管理器自启；工控机数据库和对象存储等容器采用 unless-stopped 策略，现有公网数仓隧道也已按用户明确授权启用自启。相机采集程序的原启动方式保留。

工控机需要现场一次性启动设备时，运行 `~/一键开启设备.sh`（桌面同名快捷方式）。它恢复已部署的数仓容器、观测、归档和隧道，并启动工控机雷达、只读遥测及 Jetson USB/深度相机；已有进程检查后复用，设备占用或缺失会明确报错。`--dry-run` 不执行系统命令，`--status` 只读检查，`--no-device-sources` 只恢复数仓与数据链路。此入口保留地库开关，开启时会接续原始采集；不会执行导航或行驶任务。完整选项和设备范围见 [一键启动与关闭说明](../README.md#一键启动与关闭设备工控机)。

需要结束采集设备会话时，可运行 `~/一键关闭设备.sh`（等价于启动脚本加 `--stop`）。它先停止受管数据源、等待本地原始片段收尾，再停止归档和数仓；不关闭地库开关、不删除数据卷。若 Jetson 无法连接、外部程序仍占用设备或收尾未确认，会保留必要服务并提示重试。未完成入仓的原始文件继续保留本地，下次一键启动补传；离开地库仍需在数仓页面关闭“地库采集”。

工控机配置 `~/.config/robot-cloud/archive.env`，凭据在0600 `archive-upload.json`；门禁/心跳通过数仓专用绑定目录共享。源机配置采用其自己的home路径；原相机私有optin配置为 `~/.config/robot-cloud/native-camera-archive.json`。不要把这些凭据或会话写入日志或浏览器。

实现与本次现场状态、备份和验证记录在 `~/.local/state/robot-cloud/garage-archive-20261027/`；隔离测试文件与临时schema/桶已清理，没有把夹具上传到正式数据集。当前尚未在地库开启开关进行实际长时全速采集，原相机采集程序未运行的状态必须显示等待，不能当作现场原始数据验收通过。
