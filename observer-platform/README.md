# 清洁机器人 Cloud Observer

独立云端只读 Observer，复用 RK3588 已有七页中文界面、图表，支持十七模块浏览器录制。
机器人通过 HTTPS 主动上传观测；浏览器经登录后连接云端同源 WebSocket。
ECS 无需安装 ROS2，云故障不影响本地控制。原 `/home/orangepi/code/rk3588_observer` 保留。

```
真实 ROS2 / RK3588 系统指标 → Collector → HTTPS → ECS Backend / SQLite最新状态
                                               ↓
                                      Nginx HTTPS / 登录 / WSS
                                               ↓
                                          电脑、手机、平板
```

## 目录

- `collector/`：独立ROS只读采集、媒体编码、有界队列、自动上传。
- `shared/protocol.py`：v1协议、有限数值、大小、消息与媒体验证。
- `cloud/backend/`：aiohttp认证、最新状态、重放检查、同源WS/HTTP媒体。
- `cloud/frontend/`：复用原UI资产，新增登录与云/机器人状态说明。
- `deploy/`：Docker、Nginx HTTP验收/HTTPS、systemd模板、更新/回滚/备份工具。
- `tests/`：隔离协议/后端/Collector/前端/浏览器验证。
- `docs/`：审计、架构、协议、部署、验收和安全回归。

## 开发与本地测试

Python 3.10+。云端无需ROS/OpenCV；机器人沿用已安装ROS2 Humble、psutil/OpenCV/NumPy。

```bash
cd /path/to/robot-cloud
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements-dev.txt
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q tests
```

`PYTEST_DISABLE_PLUGIN_AUTOLOAD` 只作用于该测试命令，用来避免机器人系统的ROS pytest插件干扰。
系统缺ensurepip/venv时，先在开发机准备隔离环境，或按照机器人部署手册的局部pip-target方案处理；不需要升级系统Python。
测试数据只在临时目录、随机端口或专用19088/19089测试服务中使用，不进入生产存储。
本地 HTTP 仅在显式 `ALLOW_INSECURE_LOCAL=true` 且 loopback 地址下允许，生产必须HTTPS。

## 实际使用

当前云端入口：**https://aystkit.cn**，需要登录。可上传 RK3588 系统指标及实际收到的设备反馈；相机、底盘、地图和点云没有上游消息时仍显示等待。账号获取、实际验收结果、源选择与未完成项见 [部署状态](docs/deployment_status.md)。

观测页面已按当前生产接口清理：移除未接入的 NPU/模型运行监测、只读链路没有的指令项，以及废弃默认接口；有实际接口但暂未启动的设备继续显示等待。完整删保清单见 [观测接口清单](docs/observer_interfaces.md)。

侧栏 **DBProg 数仓**（`/dbprog/`）打开原数仓的完整白色界面，保留数据集、文件、上传、回收站、数据版本、任务、AI 助手和管理页面。先登录已获批准的观测账号，再使用 DBProg 原账号登录；页面和操作权限沿用数仓原有角色。上传、预览、下载及 AI 对话均经公网同源接口，浏览器无需连接工控机内网。连接与维护见 [DBProg 接入说明](docs/dbprog.md)。

账号注册入口为 `/register`。新用户注册后自动登录等待页，仅显示“当前未获取权限”，无法访问监测数据、图片、视频或实时连接。使用原 `observer` 账号登录，在侧栏选择“账号审批”，点击对应账号的“批准权限”；等待页会自动进入监测页面。已批准用户只有观测权限，不能查看或审批其他账号。

观测页左侧 **每日测试**（`/#tests`）可手动开始、暂停、继续和结束测试统计，按北京时间记录每日时长、移动距离及测试明细。数据在后台保存，多端共享；支持近 7 日趋势和近 30 天 CSV / JSON 下载。里程无有效数据时显示“—”，部分记录会标明。使用及计量口径见 [每日测试统计](docs/daily_tests.md)。

观测页左侧 **关键故障**（`/#logs`）：后台仅记录严重故障，以及雷达 / IMU 时间异常、定位控制异常、障碍停车、数据中断等关键告警，同类问题合并计次。支持北京时间筛选与 CSV / JSON 下载；关闭网页仍持续记录，断网后补传。服务器保留最近收到的 30 天、最多 20,000 条合并记录。使用及记录范围见 [关键故障日志](docs/fault_logs.md)。

注册账号使用 3–32 位英文字母、数字、下划线、点或短横线（自动转为小写），密码为 12–512 个字符。账号及审批结果保存在持久化数据目录的 `accounts.sqlite3`，备份 `/data` 时需一并保留；密码仅保存独立随机盐的 scrypt 哈希。现有 `VIEWER_USERNAME` / `VIEWER_PASSWORD_HASH` 配置账号作为管理员，不需要重新注册。

四路原生 H.264 视频可作为独立可选链路接入，只替换原视频窗口，保留页面素材与录制、下载。浏览器访问同源 HTTPS，不依赖访问者能够连接机器人的局域网 IP；不同登录会话可同时观看，不重新打开相机。配置及带宽前提见 [原生视频接入](docs/ecs_deploy.md#四路原生-h264-视频接入)。下文的低分辨率 JPEG 链路仍保留兼容，不代表原生视频的分辨率或帧率。
相机采集的生命周期由原预览／标定程序拥有者管理；本工程的网页、视频代理与隧道只读取已有接口，不启动或停止相机采集。网页暂停与采集暂停是独立操作。

当前四路共享预览：前、后视为 640×480，左、右视为 640×360，网页均为 10 帧/秒；Jetson 本地四宫格保留原采集模式。2026-11-08 按用户现场确认校正前后、左右方向：前 camera1（USB `2.3`）、后 camera2（USB `2.4`）、左 camera4（USB `2.2.4.1`）、右 camera3（USB `2.2.1`）。编号、USB 绑定和传输别名保留，因此 `usbLeft` 实际是前相机、`usbFront` 是后相机、`usbHub2` 是左相机、`usbHub3` 是右相机；别名不能用于推断方向。共享采集和连接检测统一读取 Jetson 的 `~/.config/robot-cloud/cameras.json`，示例为 `deploy/cameras/jetson-current.json`；接线变化后需核实并同步此配置。以下旧 RK3588 切换入口与历史 JPEG 试验记录仅适用于对应部署；当前工控机为 x86，历史修复及验收记录见 [部署状态](docs/deployment_status.md#2026-10-20-中文界面与左右相机连接修复)。

2026-10-23 多端观看已改为每路相机一个共享上游，晚加入从有效关键帧起播；慢连接独立限时、断开只清理自身订阅。后台和离开相机分类立即停止视频，后台同时暂停遥测；同浏览器多个页面共享播放权，可点击“在此播放”接管。四路画质和10 FPS保持，新增前端需各终端刷新。真实双会话测得四个上游、八个订阅，上行约1.4 Mbps，不随观看端翻倍；服务器公网出口仍需按并发数规划。细节与回滚见部署状态。

## 相机使用权切换（RK3588 终端）

用户显式执行命令行切换脚本时，允许交接已知相机预览服务；普通网页访问仍不控制相机。脚本不是Linux账号／设备权限修改，不更改 `/dev/video*` 的权限。入口：

```bash
/home/orangepi/code/rk3588_observer/scripts/switch_camera_owner.sh status
/home/orangepi/code/rk3588_observer/scripts/switch_camera_owner.sh web
/home/orangepi/code/rk3588_observer/scripts/switch_camera_owner.sh peer
```

`web`：先恢复网站及只读占用检查，再检查相机；复用健康的已知原生预览或启动独立受管预览。相机忙时拒绝抢占，但网站仍正常打开，对应窗口显示实际占用状态。保留原布局、系统／机器人／雷达／点云／地图页面、精简／详细、录制与下载，仍不显示视频来源文案。高清四路仍受3 Mbps出口限制，切换脚本不会解决持续带宽不足，也不擅自降低画质。

`peer`：停止身份已验证的网页相机预览，把设备交给标定／其他程序；不自动启动对方未知程序，不结束标定GUI。网站和只读状态／视频转发继续可用：实际有其他程序持有该路设备才显示“相机被其他程序占用”，没启动预览显示“相机预览未启动”，缺设备显示“相机未连接”，探测过期显示“占用状态未知”。停止浏览器播放不会停止对方采集。

切回 `web` 前保存并关闭标定／其他采集。切回网页时若存在未知占用者或缺设备，会拒绝操作；服务身份不可确认或切换并发也会拒绝，不强杀进程。`peer` 可在设备缺失时释放已知预览，不终止未知占用者。同一个Linux用户下也不能阻止另一个终端绕过脚本另开采集，请双方按此入口交接。可在模式后加 `--dry-run` 只预演，`status`／预演不写锁或模式文件、不切换服务。实际切换采用RK与Jetson双层互斥；启动失败只清理本轮新建的预览，不追杀未知／被他人替换的来源；此前为交接停止的旧预览不会自动重开，以免与新出现的标定进程抢占设备。

辅助程序独立安装到Jetson `~/.local/share/robot-cloud/camera_owner.py`，不修改原项目代码。ECS接收端使用经用户批准的专用受限公钥，仅能 `receiver-status`／`receiver-start`，不能登录shell、停止服务、转发端口或更改账号；不依赖反复解锁管理员部署密钥。

独立只读网关 `~/.local/share/robot-cloud/camera_status_gateway.py` 仅监听Jetson `127.0.0.1:8081`，后台检查进程已有设备描述符并转发现有8080预览，不打开视频设备。占用信息最长6秒有效，包含传输耗时；不会从peer模式、HTTP失败或无图推断被占用，不把部分可见的“未发现占用”当作绝对空闲。仅已知四路拥有此接口，彩色／深度相机保持原数据链路。

## 真实数据边界

没有发布者/没有真实消息时显示等待数据；云网页和WS在线不代表机器人在线。
机器人心跳超过10秒未更新显示离线；观测超过5秒标记STALE，字段/Page保留上游更严格期限。
ROS图像默认1 FPS、点云默认1 Hz/1500点；HTTP相机默认兼容原每路最高1 FPS，本次显式配置为2 FPS，互不影响。静态地图内容去重，连接恢复会重发。
「实时画面 → 相机」保留不同接线的独立身份，不复用方向不明的相机。2026-10-12 用户授权四路低分辨率试验，当前使用独立 USB 采集入口与显式 `jetson-hub4`：前视、左视、扩展接口2.1.2/2.1.3；扩展接口不标作后视或深度图。四台驱动均实测为640×360 MJPG，原相机源码和配置未修改。20:20按用户要求撤销320×180网络缩图，relay恢复640×480上限（当前640×360源不再缩小），quality60及有界连接复用保持；HTTP预览仍显式 `COLLECTOR_HTTP_CAMERA_FPS=2`，每路最高2 FPS，原USB采集与ROS图像频率不改。这不等于恢复试验前的硬件高清采集参数，恢复后持续结果见[部署状态](docs/deployment_status.md#2026-10-12-网络预览画质恢复2020)。`jetson-direct3` 和默认 `legacy3` 保留用于对应接线，不能未经设备审计直接切换。设置见 [Collector部署手册](docs/robot_collector.md#四路-usb-低分辨率独立采集试验显式授权)。
协议兼容17媒体项（9相机），当前页面显示6张相机卡：四路USB预览和用途不同的彩色／深度输出。鱼眼、旧后视、旧接口2.1不再作为实时画面卡片，也不发起相应取图请求；协议/API及详细ROS诊断保留兼容，不把未发现发布者当作已删除实体设备。当前 `jetson-hub4` 启用15媒体项、队列17项，后视与已移除的直连接口2.1不上传。`jetson-direct3` 和开启HTTP的 `legacy3` 均为14媒体/16队列项；若切回不同接线，需同时核对页面显示清单。四路真实公网JPEG与帧递增短时验收已通过；持续监测及掉帧如实记录在 [部署状态](docs/deployment_status.md)，不保证零断流。独立relay已显式开启有界HTTP连接复用，减少每帧新建SSH通道的往返；上传队列合并保持公平、剔除过时实时帧。完整回归 `620 passed, 27 subtests passed`。独立低清源是手动试验服务，未启用开机自启；原预览恢复方案保留。
实时画面新增「二维雷达扫描」：蓝海 `/bluesea_new/scan` 与通用 `/scan`，按真实 LaserScan 距离和角度绘制本地 XY 平面，支持独立录制、停止后下载和重新录制放弃旧片段。接口存在不等于设备在线；无消息保持等待，不做 TF 融合或伪造三维高度。
位置/姿态/路径与坐标系保留为诊断摘要；原页面没有地图定位/路径叠图，本轮不做未经验证的坐标融合。
观测与媒体仅保留最新状态及上传顺序检查点，不提供视频存档；故障日志独立保留 30 天，且有条数上限。
相机短暂过期时，浏览器最多保留最后一帧10秒并明确标注“已过期 · 最后一帧（非实时）”；立即停录，重复状态不续期，新有效帧自动恢复。异常、来源切换、离开分类或认证失效会清理旧图。2秒真实新鲜度判断不变。
浏览器已解码且取得强ETag的相机采用最短250ms的有界条件检查，每路最多一个在途请求；未变帧返回304，不重复下载JPEG。304仍携带当前帧龄，不能延长原帧期限或把过期画面重新标为实时；没有可用ETag时保持原1秒取图兼容策略。此修复针对取图相位与公网延迟，不承诺高延迟下永不出现真实过期。
ECS及域名已提供并开始实际部署，当前进度、访问地址及未完成项见 [部署状态](docs/deployment_status.md)。域名解析正常或容器健康不等于公网、HTTPS与真实设备数据已通过验收。

本工程处于现有上层脏工作树旁边；正式Git流程应先把本目录初始化为独立私有仓库，避免推送父目录中的机器人控制代码或生成产物。

地库自动原生归档：在完整数仓的“地库采集”独立模块开启或关闭；按北京时间、传感器和实际时间段归档，断网本地保存。部署与边界见 [地库归档说明](docs/garage_archive.md)。
### 一键启动相机与关闭设备（工控机）

设备电源开启、Jetson 与工控机同网后，在工控机终端执行：

```bash
~/一键开启设备.sh
```

桌面提供“一键开启相机”“一键关闭设备”和“相机启动状态”快捷方式。首次双击若桌面提示未信任，右键选择“允许启动”。详细入口为 `~/.local/share/robot-cloud/deploy/scripts/start_all_devices.sh`。

默认只启动四路 USB 相机、P100R 彩色/深度相机、网页预览、YOLO/ArUco 识别及必要观测/视频传输。已有相机程序会被检查并复用，被其他程序占用时保留原程序并报告。默认入口不会拉起雷达、FAST-LIO、底盘、数仓或原始归档。网页相机页面叠加有效的 YOLO 检测框；深度画面中心显示同一原始深度帧的测距标记，单位 cm、1 位小数，无有效深度显示 `-- cm`。测距为中心小区域的 Z 深度，不把未对齐的彩色框位置当作深度坐标。

```bash
~/一键开启设备.sh                       # 默认仅启动相机、识别与网页传输
~/一键开启设备.sh --dry-run             # 预演相机启动，不连接设备
~/一键开启设备.sh --status              # 只检查相机范围，不启动服务
~/一键开启设备.sh --cameras-only --stop # 仅关闭相机及视频链路
~/一键开启设备.sh --all-devices         # 显式启动原完整设备栈
~/一键开启设备.sh --all-devices --status # 检查完整设备栈
```

`--all-devices` 保留原功能：启动已部署的 DBProg 六个容器、观测、原生归档、文件同步、数仓隧道、视频隧道，以及 MID360/IMU/FAST-LIO、STL-19P、蓝海雷达、底盘只读遥测和相机。两台二维雷达分别使用 `/scan` 与 `/bluesea_new/scan`。完整模式可使用 `--no-camera-source` 跳过相机源、`--no-device-sources` 仅恢复数据服务。

支持 `--no-warehouse` 跳过数仓，`--ready-timeout 120` 调整数仓就绪等待秒数。缺设备、缺服务或 Jetson 离线会列明失败并返回非零退出码，其余链路继续处理。数据库只启动已有容器，保留当前镜像、配置和数据；后端就绪但 Web 代理因旧容器地址失败时，会检查 Nginx 配置并平滑重载一次。不会构建、迁移、初始化账号或自动启用新的开机服务。传感器与驱动运行状态不等于真实数据验收，请在观测页核对实时画面与雷达数据。

关闭整套设备与数据服务时，双击桌面“一键关闭设备”，或运行：

```bash
~/一键关闭设备.sh
# 等价命令：
~/一键开启设备.sh --stop

~/一键关闭设备.sh --dry-run       # 仅预演关闭顺序
~/一键关闭设备.sh --no-warehouse  # 关闭设备与数据链路，保留本机数仓
```

关闭顺序为 Jetson 原相机与深度相机、工控机受管雷达及只读遥测、原始数据归档与同步、观测与隧道，最后停止数仓应用及存储容器。停止数据源后等待新鲜状态确认队列清空和活动片段收尾，通常约15秒；超时、设备停止失败或 Jetson 离线时，脚本返回失败并保留尚需使用的归档、同步与数仓，便于处理后重试。只停止本入口管理的精确服务，不按进程名关闭其他终端启动的程序；发现外部设备进程仍在运行会说明保留原因。

已开启“地库采集”时，完整采集流程为“`~/一键开启设备.sh --all-devices` → 自动采集保存 → 一键关闭设备”。收到原始数据后，即使只采集几秒，也会按实际时段收尾，无需凑满一小时。启动尚未结束时点击关闭，会等待当前操作结束后自动继续；请保留关闭窗口，等到提示完成再断电。保存到本地和上传入仓是两个阶段，关闭不承诺所有文件立即出现在公网数仓。

关闭保留地库开关、原始文件与数据库卷，不等待无限量上传；已落盘但尚未完成入仓的片段下次启动补传。关闭成功只代表受管服务已停止，电脑仍然开机。手动停止后需要再次执行一键启动恢复数仓访问与补传；Docker 的 `unless-stopped` 策略不会把手动停止的容器自行重新拉起。当前验证使用隔离模拟，没有替用户关闭实机设备。

本入口用于设备采集与观测，不执行导航或行驶任务。地库开关保持原值：进入地库后在数仓“地库采集”独立模块开启，离开后关闭。若旧蓝海驱动仍发布 `/scan`，脚本会报告冲突，需要现场结束旧蓝海入口后重新执行。本次仅完成脚本和隔离验证，真实设备由用户现场启动。
